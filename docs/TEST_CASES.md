# ตารางบันทึกผลการทดสอบระบบและคุณภาพข้อมูล (Test Cases & Results)
**โครงงาน:** Mini Project Database ร้านขาย E-Book  
**รายวิชา:** Database Mini Project  

บันทึกการทดสอบระบบครอบคลุมทั้งเส้นทางการทำงานหลัก (Happy Path), การตรวจสอบความปลอดภัยของสิทธิ์การดาวน์โหลด (Security Control), และการรับมือกับข้อมูลที่ผิดพลาด (Error Handling & Constraints) รวม **9 กรณีทดสอบ** (เกินเกณฑ์ขั้นต่ำ 8 กรณี)

---

| ลำดับ (No.) | กรณีทดสอบ (Test Case Scenario) | ข้อมูลนำเข้า (Test Input Data) | ผลลัพธ์ที่คาดหวัง (Expected Result) | ผลลัพธ์ที่เกิดขึ้นจริง (Actual Result) | สถานะ (Status) | วิธีแก้ไข / หมายเหตุ (Remediation Note) |
|:---:|---|---|---|---|:---:|---|
| **TC-01** | สมัครสมาชิกใหม่ด้วยข้อมูลที่ถูกต้องครบถ้วน | ชื่อ: นายทดสอบ ระบบดี<br>Username: testuser99<br>Email: test99@test.com<br>Password: pass123 | บันทึกสมาชิกลงในตาราง `users` สำเร็จ สร้างตะกร้าสินค้าอัตโนมัติ และ Redirect ไปยังหน้าเข้าสู่ระบบ | บันทึกสำเร็จ ได้รับ `user_id` ใหม่ และรหัสผ่านถูก Hash ด้วย Werkzeug Scrypt | **ผ่าน (PASS)** | - |
| **TC-02** | สมัครสมาชิกด้วย Username หรือ Email ซ้ำในระบบ (Data Constraint Test) | สมัครซ้ำด้วย Username: `customer1` หรือ Email: `customer1@test.com` | ระบบปฏิเสธการลงทะเบียน แจ้งเตือนข้อผิดพลาด และไม่เกิด Duplicate Key Error ในฐานข้อมูล | แจ้งเตือน *"ชื่อผู้ใช้หรืออีเมลนี้มีในระบบแล้ว"* ตามเงื่อนไข UNIQUE Constraint | **ผ่าน (PASS)** | ดักจับ Exception และแจ้งเตือนผ่าน Flash Message ให้ผู้ใช้ทราบ |
| **TC-03** | ค้นหาหนังสือและกรองตามหมวดหมู่ | ค้นหาคำว่า *"Python"* หรือเลือกหมวด *"วิทยาศาสตร์ข้อมูล & AI"* | แสดงเฉพาะหนังสือที่มีคำค้นในชื่อเรื่อง/คำอธิบาย หรืออยู่ในหมวดหมู่ที่เลือกอย่างถูกต้อง | แสดงผลลัพธ์ตรงตามเงื่อนไข พร้อมแสดงป้ายจำนวนหนังสือที่พบ | **ผ่าน (PASS)** | ใช้ SQL `LIKE` และ `b.category_id = ?` แบบ parameterized query ป้องกัน SQL Injection |
| **TC-04** | การจัดการตะกร้าสินค้า (เพิ่ม, ปรับจำนวน, ลบ) | เลือกหนังสือ #1 เพิ่มลงตะกร้า กดปุ่ม (+) และ (-) และลบรายการ | ตาราง `cart_items` อัปเดตจำนวนถูกต้อง คำนวณราคารวม (Subtotal) สอดคล้องกับราคาต่อหน่วย | ตะกร้าคำนวณยอดรวมถูกต้อง และลบรายการออกจากตารางเมื่อสั่งลบ | **ผ่าน (PASS)** | ป้องกันจำนวนติดลบด้วยเงื่อนไข `CHECK(quantity > 0)` |
| **TC-05** | การสั่งซื้อและชำระเงินจำลอง (Order & Payment) | เลือกชำระผ่าน PromptPay QR แนบสลิปจำลอง `mock_slip_1.png` | สร้างคำสั่งซื้อในสถานะ `PENDING` สร้างรายการ `order_items` และบันทึก `payments` ล้างตะกร้าสินค้า | สร้าง `ORD-YYYYMMDD-XXXX` สถานะ `PENDING` และบันทึกหลักฐานจำลองสำเร็จ | **ผ่าน (PASS)** | - |
| **TC-06** | **ทดสอบความปลอดภัย: พยายามดาวน์โหลดก่อนผู้ดูแลยืนยันคำสั่งซื้อ (Security Rule 2.2)** | ผู้ใช้เข้าถึง URL `/download/<token>` หรือ `/download/ebook/<order_id>/<book_id>` ขณะที่คำสั่งซื้อยังเป็น `PENDING` หรือ `CANCELLED` | **ระบบต้องปฏิเสธการดาวน์โหลดอย่างเด็ดขาด (403 Forbidden)** ห้ามเปิดไฟล์ให้ลูกค้าเด็ดขาด | ระบบไม่อนุญาต แจ้งเตือน *"ไม่สามารถดาวน์โหลดได้: คำสั่งซื้อยังไม่ได้รับการยืนยัน"* และส่ง HTTP 403 Forbidden | **ผ่าน (PASS)** | ตรวจสอบ `o.status == 'CONFIRMED'` และกรรมสิทธิ์ความเป็นเจ้าของในระดับ Backend Server ทุกครั้งก่อนส่งไฟล์ |
| **TC-07** | ผู้ดูแลร้านตรวจสอบหลักฐานและเปลี่ยนสถานะคำสั่งซื้อ | ผู้ดูแลระบบ Login เป็น `admin` แล้วกดปุ่ม *"ยืนยันคำสั่งซื้อ"* ที่คำสั่งซื้อ #ORD-xxx | สถานะในตาราง `orders` เปลี่ยนเป็น `CONFIRMED`, `payments` เปลี่ยนเป็น `VERIFIED`, และสร้าง/เปิดสิทธิ์ใน `download_links` | สถานะอัปเดตเรียบร้อย ระบบสร้าง `download_token` สำหรับหนังสือทุกเล่มในออเดอร์นั้น | **ผ่าน (PASS)** | - |
| **TC-08** | ดาวน์โหลดไฟล์ E-Book หลังได้รับการยืนยันแล้ว | ลูกค้ากดปุ่ม *"ดาวน์โหลด PDF"* ในคำสั่งซื้อที่สถานะ `CONFIRMED` | ผู้ใช้ได้รับไฟล์ PDF หนังสือตัวอย่างจริง (`Content-Type: application/pdf`) และเพิ่ม `download_count` ในตาราง `download_links` | เซิร์ฟเวอร์ส่งไฟล์ PDF สำเร็จ 200 OK และอัปเดตจำนวนครั้งที่โหลดในฐานข้อมูลถูกต้อง | **ผ่าน (PASS)** | จัดทำไฟล์ตัวอย่าง PDF ในโฟลเดอร์ `static/downloads/` รองรับการดาวน์โหลดจริง |
| **TC-09** | ตรวจสอบความถูกต้องของข้อมูลราคาและจำนวน (Validation & CHECK Constraints) | ป้อนราคาหนังสือเป็นจำนวนติดลบ เช่น `-100.00` ในหน้าเพิ่ม E-Book | ระบบฐานข้อมูลปฏิเสธข้อมูลตามข้อจำกัด `CHECK(price >= 0)` | ไม่สามารถบันทึกได้ และฟอร์มหน้าเว็บมีการระบุ `min="0"` ควบคุมทั้งฝั่ง Frontend และ Database | **ผ่าน (PASS)** | บังคับใช้ Database Constraints คู่กับ Client-side HTML5 validation |
