# ฟังก์ชันที่ 5: ระบบควบคุมความปลอดภัยและการส่งมอบไฟล์ดาวน์โหลด (Secure Download & Delivery)
**โครงงาน:** Mini Project Database ร้านขาย E-Book  
**หมวดหมู่:** เงื่อนไขการส่งสินค้าและกติกาความปลอดภัย ตามข้อกำหนดหัวข้อ 2.2  

---

## 1. วัตถุประสงค์ของฟังก์ชัน
เพื่อให้ระบบสามารถส่งมอบไฟล์ E-Book ดิจิทัล (PDF) ให้แก่ลูกค้าได้อย่างถูกต้อง ปลอดภัย และ**เป็นไปตามข้อกำหนดความปลอดภัยที่เข้มงวดที่สุดในใบงาน (ข้อ 2.2)**: 
> *"ระบบต้องไม่เปิดลิงก์ของหนังสือที่ลูกค้ายังไม่ได้ซื้อ หรือคำสั่งซื้อยังไม่ยืนยัน โดยต้องควบคุมเงื่อนไขการเข้าถึงทั้งในระดับข้อมูลและหน้าจอ"*

---

## 2. หน้าจอและเส้นทางที่เกี่ยวข้อง (Routes & Templates)
* **`/order/<int:order_id>`** (`templates/order_detail.html`): หน้าแสดงสถานะคำสั่งซื้อและปุ่มดาวน์โหลด (แสดงปุ่มเฉพาะเมื่อยืนยันแล้ว)
* **`/download/<token>`**: เส้นทางดาวน์โหลดไฟล์ด้วย Secure UUID Token
* **`/download/ebook/<int:order_id>/<int:ebook_id>`**: เส้นทางดาวน์โหลดทางตรงพร้อมตรวจสอบสิทธิ์ครบวงจร

---

## 3. สถาปัตยกรรมการรักษาความปลอดภัย 4 ชั้น (4-Tier Security Check)

ก่อนที่เซิร์ฟเวอร์จะยอมปล่อยไฟล์หนังสือให้แก่ไคลเอนต์ ระบบจะทำการตรวจสอบตามลำดับดังต่อไปนี้:

```
[ผู้ใช้ร้องขอการดาวน์โหลดไฟล์]
          │
          ▼
┌─────────────────────────────────┐
│ 1. การยืนยันตัวตน (Auth Check)    │ ── ไม่ผ่าน ──► Redirect ไปหน้า Login
│ ผู้ใช้เข้าสู่ระบบหรือยัง?          │
└─────────────────────────────────┘
          │ ผ่าน
          ▼
┌─────────────────────────────────┐
│ 2. ตรวจสอบความเป็นเจ้าของ (Owner) │ ── ไม่ผ่าน ──► HTTP 403 Forbidden
│ เป็นคำสั่งซื้อของผู้ใช้คนนี้จริงไหม? │                (ห้ามโหลดของคนอื่น)
└─────────────────────────────────┘
          │ ผ่าน
          ▼
┌─────────────────────────────────┐
│ 3. ตรวจสอบสถานะคำสั่งซื้อ (Status)│ ── ไม่ผ่าน ──► HTTP 403 Forbidden
│ สถานะเป็น 'CONFIRMED' หรือไม่?   │                (ห้ามโหลดก่อนอนุมัติสิทธิ์)
└─────────────────────────────────┘
          │ ผ่าน
          ▼
┌─────────────────────────────────┐
│ 4. ตรวจสอบความถูกต้องของ Token   │ ── ไม่ผ่าน ──► HTTP 404 Not Found
│ โทเค็นมีอยู่ในตาราง & Active?    │                หรือ Token หมดอายุ
└─────────────────────────────────┘
          │ ผ่าน
          ▼
[อัปเดต download_count + 1 ในตาราง download_links]
          │
          ▼
[ส่งมอบไฟล์ PDF ให้ดาวน์โหลดลงเครื่องทันที (HTTP 200 OK)]
```

## 4. ลำดับขั้นตอนการทำงาน (Step-by-Step Flow)

### 4.1 กรณีคำสั่งซื้อยังไม่ได้รับการยืนยัน (`status = 'PENDING'` หรือ `'CANCELLED'`)
1. ลูกค้าเปิดดูหน้าคำสั่งซื้อของตนเอง
2. **ในระดับหน้าจอ (Frontend Control):**
   * ปุ่มดาวน์โหลดจะถูกปิดการใช้งาน (Disabled) และแสดงป้าย *"รอตรวจสอบ / รออนุมัติสิทธิ์"*
   * แสดงกล่องข้อความเตือนชี้แจงเงื่อนไขความปลอดภัยตามข้อกำหนดวิชา
3. **ในระดับเซิร์ฟเวอร์ (Backend Control):**
   * หากมีผู้ใช้พยายามพิมพ์ URL หรือแอบใส่ Token โดยตรง เซิร์ฟเวอร์จะสั่งหยุดการทำงานทันที และตอบกลับด้วยรหัส **`HTTP 403 Forbidden`** พร้อมข้อความ *"ไม่อนุญาต: คำสั่งซื้อนี้ยังไม่ได้รับการยืนยันการชำระเงิน"*

### 4.2 กรณีคำสั่งซื้อได้รับการยืนยันแล้ว (`status = 'CONFIRMED'`)
1. เมื่อผู้ดูแลร้านตรวจสอบสลิปและกดอนุมัติ ระบบจะสร้างโทเค็นลับ (UUIDv4) ประจำรายการในตาราง `download_links`
2. **ในระดับหน้าจอ:** ปุ่มจะเปลี่ยนเป็นสีเขียวเด่นชัดเขียนว่า **"ดาวน์โหลด E-Book (PDF)"**
3. ลูกค้าคลิกปุ่มดาวน์โหลด:
   * เซิร์ฟเวอร์ส่งคำสั่ง SQL ไปตรวจสอบโทเค็น
   * เพิ่มสถิติจำนวนครั้งที่ดาวน์โหลด: `download_count = download_count + 1`
   * สตรีมไฟล์ PDF ผ่านฟังก์ชัน `send_from_directory()` ในโหมด `as_attachment=True`
4. เบราว์เซอร์จะบันทึกไฟล์ PDF ลงในเครื่องของลูกค้าทันที

## 5. ตารางฐานข้อมูลที่เกี่ยวข้อง (Database Tables)

| ชื่อตาราง | บทบาทในฟังก์ชันนี้ | ฟิลด์สำคัญที่เกี่ยวข้อง |
|---|---|---|
| **`download_links`** | เก็บโทเค็นและสิทธิ์การเข้าถึงไฟล์ | `download_id`, `order_id`, `ebook_id`, `user_id`, `download_token`, `download_count`, `is_active` |
| **`orders`** | ตรวจสอบสถานะการยืนยัน | `order_id`, `user_id`, `status` ('CONFIRMED') |
| **`ebooks`** | เก็บที่อยู่ไฟล์จริงบนเซิร์ฟเวอร์ | `ebook_id`, `title`, `download_file_url` |

---

## 6. คำสั่ง SQL เบื้องหลังการทำงาน (Underlying SQL)

### ตรวจสอบสิทธิ์การดาวน์โหลดแบบรวมตาราง (Validation Query)
```sql
SELECT 
    dl.download_id,
    dl.download_token,
    dl.download_count,
    dl.is_active,
    o.status AS order_status,
    b.title,
    b.download_file_url
FROM download_links dl
JOIN orders o ON dl.order_id = o.order_id
JOIN ebooks b ON dl.ebook_id = b.ebook_id
WHERE dl.download_token = :token;
```

### นับสถิติจำนวนครั้งที่มีการดาวน์โหลดจริง
```sql
UPDATE download_links 
SET download_count = download_count + 1 
WHERE download_id = :download_id;
```
