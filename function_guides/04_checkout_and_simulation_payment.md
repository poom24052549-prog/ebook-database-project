# ฟังก์ชันที่ 4: การสั่งซื้อและการชำระเงินจำลอง (Checkout & Simulated Payment)
**โครงงาน:** Mini Project Database ร้านขาย E-Book  
**หมวดหมู่:** ส่วนหน้าร้าน (ผู้ใช้งาน) ตามข้อกำหนดหัวข้อ 2.1  

---

## 1. วัตถุประสงค์ของฟังก์ชัน
เพื่อให้ลูกค้าสามารถยืนยันคำสั่งซื้อจากสินค้าในตะกร้า, เลือกวิธีชำระเงินแบบจำลอง (Simulation), แนบหลักฐานหรือสลิปการโอนเงินจำลอง, และระบบทำการบันทึกข้อมูลคำสั่งซื้อ (Orders), รายการย่อย (Order Items) พร้อม Snapshot ราคาประวัติ และบันทึกการชำระเงิน (Payments) เข้าสู่ฐานข้อมูลอย่างเป็นระบบ

---

## 2. หน้าจอและเส้นทางที่เกี่ยวข้อง (Routes & Templates)
* **`/checkout`** (`templates/checkout.html`): หน้าตรวจสอบรายการสั่งซื้อ เลือกวิธีชำระเงิน และแนบสลิปจำลอง
* **`/my-orders`** (`templates/my_orders.html`): หน้าดูประวัติคำสั่งซื้อทั้งหมดของลูกค้า
* **`/order/<int:order_id>`** (`templates/order_detail.html`): หน้ารายละเอียดคำสั่งซื้อและใบเสร็จจำลอง

---

## 3. ลำดับขั้นตอนการทำงาน (Step-by-Step Flow)

### 3.1 การเข้าสู่หน้าชำระเงิน (Proceed to Checkout)
1. ลูกค้ากดปุ่ม **"ไปที่ขั้นตอนชำระเงิน"** จากหน้าตะกร้าสินค้า
2. ระบบตรวจสอบสินค้าในตะกร้า หากตะกร้าว่างเปล่าจะไม่อนุญาตและแจ้งเตือนให้เลือกหนังสือก่อน
3. ระบบคำนวณยอดเงินรวมสุทธิที่ต้องชำระ และแสดงตารางสรุปรายการหนังสือ

### 3.2 การเลือกช่องทางชำระเงินแบบจำลอง (Payment Simulation)
ตามข้อกำหนดใบงานข้อ 2.1 *"ให้ผู้ใช้เลือกวิธีชำระเงินหรือแนบหลักฐานจำลอง ห้ามใช้ข้อมูลบัตรหรือบัญชีจริง"*:
* **ช่องทางที่ 1: พร้อมเพย์ QR Code จำลอง (PromptPay QR):** แสดงการ์ด PromptPay QR Code จำลองที่เจนจากยอดเงินจริงในตะกร้า พร้อมระบุเลขบัญชีจำลอง
* **ช่องทางที่ 2: โอนผ่านบัญชีธนาคาร (Bank Transfer):** แสดงรายละเอียดธนาคารกสิกรไทย เลขบัญชีจำลอง
* **ช่องทางที่ 3: บัตรเครดิต/เดบิตจำลอง (Mock Credit Card Sandbox):** แสดงข้อมูลหมายเลขบัตรทดสอบแบบ Read-only

### 3.3 การแนบหลักฐานจำลองและกดสั่งซื้อ (Place Order)
1. ลูกค้าสามารถเลือกอัปโหลดไฟล์ภาพสลิปจำลอง (PNG/JPG) หรือพิมพ์รหัสอ้างอิงการโอน
   *(หากไม่ได้อัปโหลดไฟล์ ระบบจะดึงภาพสลิปจำลองเริ่มต้นให้โดยอัตโนมัติ เพื่อความสะดวกในการทดสอบ)*
2. ลูกค้ากดปุ่ม **"ยืนยันการสั่งซื้อและส่งหลักฐานจำลอง"**

### 3.4 การประมวลผลธุรกรรมในฐานข้อมูล (Database Transaction Flow)
ระบบดำเนินการ 4 ขั้นตอนต่อเนื่องกัน:
1. **สร้างหมายเลขคำสั่งซื้อเฉพาะ (Unique Order Number):** ในรูปแบบ `ORD-YYYYMMDD-XXXX` (เช่น `ORD-20260928-1005`)
2. **บันทึกหัวคำสั่งซื้อ (`orders`):** บันทึกรหัสผู้ใช้, ยอดรวมสุทธิ, วันที่ และกำหนดสถานะเริ่มต้นเป็น **`PENDING`** (รอตรวจสอบ)
3. **บันทึกรายการย่อย (`order_items`):** วนลูปอ่านรายการในตะกร้า และคัดลอกราคา ณ ปัจจุบันมาเก็บเป็น `unit_price` (Price Snapshotting) เพื่อป้องกันปัญหาราคาเปลี่ยนในอนาคต พร้อมคำนวณ `subtotal`
4. **บันทึกข้อมูลการชำระเงิน (`payments`):** บันทึกวิธีชำระ, ยอดเงิน, ที่อยู่ไฟล์ภาพสลิป, และกำหนดสถานะการชำระเป็น `PENDING`
5. **ล้างตะกร้าสินค้า (`cart_items`):** ลบรายการในตะกร้าของผู้ใช้ออกทั้งหมด เพื่อคืนสถานะตะกร้าว่าง
6. **ผลลัพธ์:** แสดง Flash Message สำเร็จ และนำทางลูกค้าไปยังหน้า `/my-orders`

## 4. ตารางฐานข้อมูลที่เกี่ยวข้อง (Database Tables)

| ชื่อตาราง | บทบาทในฟังก์ชันนี้ | ฟิลด์สำคัญที่เกี่ยวข้อง |
|---|---|---|
| **`orders`** | บันทึกหัวเอกสารคำสั่งซื้อ | `order_id`, `order_number`, `user_id`, `total_amount`, `status` ('PENDING') |
| **`order_items`** | บันทึกรายการหนังสือในบิล | `order_item_id`, `order_id`, `ebook_id`, `unit_price`, `quantity`, `subtotal` |
| **`payments`** | บันทึกการชำระเงินและสลิป | `payment_id`, `order_id`, `payment_method`, `amount`, `slip_image`, `payment_status` |
| **`cart_items`** | เคลียร์ตะกร้าสินค้าหลังสั่งซื้อ | `cart_item_id`, `cart_id` |

## 5. คำสั่ง SQL เบื้องหลังการทำงาน (Underlying SQL)

### บันทึกหัวคำสั่งซื้อ (Orders Table)
```sql
INSERT INTO orders (order_number, user_id, total_amount, status, notes)
VALUES ('ORD-20260928-1005', :user_id, :total_amount, 'PENDING', 'สั่งซื้อผ่านระบบออนไลน์');
```

### บันทึกรายการหนังสือย่อย (Order Items Table)
```sql
INSERT INTO order_items (order_id, ebook_id, unit_price, quantity, subtotal)
VALUES (:order_id, :ebook_id, :unit_price, :quantity, :subtotal);
```

### บันทึกข้อมูลการชำระเงินและภาพสลิปจำลอง (Payments Table)
```sql
INSERT INTO payments (order_id, payment_method, amount, slip_image, payment_status, admin_notes)
VALUES (:order_id, 'PROMPTPAY_QR', :total_amount, '/static/uploads/slips/slip_001.png', 'PENDING', 'รอผู้ดูแลตรวจสอบยอดเงิน');
```

### เคลียร์รายการในตะกร้าหลังสั่งซื้อสำเร็จ
```sql
DELETE FROM cart_items 
WHERE cart_id = (SELECT cart_id FROM carts WHERE user_id = :user_id);
```

## 6. ข้อจำกัดข้อมูลและความปลอดภัย (Constraints & Security)
* **`UNIQUE(order_number)`:** เลขที่คำสั่งซื้อห้ามซ้ำกันในระบบ
* **`CHECK(status IN ('PENDING', 'CONFIRMED', 'CANCELLED'))`:** ควบคุมสถานะให้มีค่าเฉพาะที่ระบบอนุญาต
* **`CHECK(total_amount >= 0)` & `CHECK(unit_price >= 0)`:** ป้องกันความผิดพลาดของยอดเงินติดลบ
* **สถานะเริ่มต้นปลอดภัย:** คำสั่งซื้อใหม่ทุกรายการจะต้องเริ่มต้นที่สถานะ `PENDING` เท่านั้น และยังไม่ได้รับสิทธิ์ดาวน์โหลดไฟล์จนกว่าผู้ดูแลระบบจะตรวจสอบ
